# Transcendify — софтуер за търговия по борси

Не е борса. Не държи парите ти. Свързва се към **OKX** (изпълнение), **Polygon**
(независими пазарни данни) и **Claude** (преценка), а решенията за риск се вземат
в код, който можеш да прочетеш и тестваш.

Проектът вече **не зависи от base44** — нито SDK, нито акаунт, нито техен сървър.
Всичко върви локално: `engine/` е двигателят на Node, `src/` е интерфейсът на React.

---

## Първо най-важното: „търговия без загуби" не съществува

Няма настройка, модел или стратегия, която да махне губещите сделки. Всяка
система, която обещава това, или лъже, или още не е загубила.

Постижимото е друго и е достатъчно: **малки, ограничени и предвидими загуби**,
така че печелившите сделки да ги надвишават. Точно затова:

- Всяка позиция има стоп **на борсата**, не в кода. Спре ли токът, стопът стои.
- Размерът се смята от разстоянието до стопа, за да е загубата еднаква в лева.
- Има дневен таван на загубата и таван на спадането от върха, които спират всичко.
- Сделка без пресметнато предимство **не се прави**.

## Защо старата версия губеше

Старите настройки бяха `TAKE_PROFIT_PCT = 0.35`, `STOP_LOSS_PCT = -0.20`, а
таксите — 0.1% на страна:

| | брутно | нето след такси |
|---|---|---|
| печеливша сделка | +0.35% | **+0.15%** |
| губеща сделка | −0.20% | **−0.40%** |

Губещата струва 2.67 пъти повече от печелившата. За да се излезе на нула са
нужни **72.7% печеливши сделки** — а с позволения спред от 0.08% при пазарни
поръчки, **около 87%**. Това не е проблем в изпълнението; стратегията беше
губеща по конструкция.

Провери сам с текущите настройки:

```bash
npm run engine:cli edge
```

```
┌────────┬────────┬───────────────────┬──────────────────┐
│ стоп % │ цел %  │ нужни печеливши % │ нужни + резерв % │
├────────┼────────┼───────────────────┼──────────────────┤
│ 0.40   │ 0.80   │ 55.0              │ 60.0             │
│ 1.00   │ 2.00   │ 42.0              │ 47.0             │
│ 2.00   │ 4.00   │ 37.7              │ 42.7             │
└────────┴────────┴───────────────────┴──────────────────┘
```

42% е постижимо. 87% — не.

## Какво беше поправено

| # | Проблем | Как е сега |
|---|---|---|
| 1 | Стоповете живееха в кода (`ordType: 'market'` и толкова). Рестарт или прекъсната мрежа = позиция без стоп. | `placeProtectedEntry` слага стоп и цел **на OKX**, закачени за входната поръчка. Ако борсата откаже защитата, позицията се затваря веднага. |
| 2 | Дневният лимит четеше `t.profit_loss`, което никой не записваше — сборът беше вечно нула и лимитът не сработи нито веднъж. | `closeTrade` смята и записва `realized_pnl` (с извадени такси). Затворена сделка без резултат е **грешка**, не нула. |
| 3 | `order.quantity * (order.limit_price \|\| 1000)` — при пазарна поръчка активът се смяташе за 1000 долара, тоест проверката за размер минаваше винаги. | Размерът се смята по текущата котировка (`bid`/`ask`), от разстоянието до стопа. |
| 4 | Фиксирани проценти за цел и стоп при всякакъв пазар. | Стопът е кратно на ATR; целта е кратно на риска (`REWARD_RISK_RATIO`). |
| 5 | Бектестът броеше такси, но не и спред. | Спредът се мери на живо и участва в сметката за предимство. |

## Пускане

```bash
# 1. интерфейсът
npm install

# 2. двигателят
npm --prefix engine install
cp engine/.env.example engine/.env      # попълни ключовете

# 3. пускане (два прозореца)
npm run engine                          # http://127.0.0.1:8787
npm run dev                             # http://localhost:5173
```

Без ключове двигателят работи в режим на хартия и чете публичните данни на OKX.
Това е нарочно — първо гледаш какво щеше да се случи, после залагаш пари.

### Проверка

```bash
npm run engine:test          # 16 теста върху сметките за риск
npm run engine:cli edge      # колко печеливши сделки трябват за нула
npm run engine:cli scan      # един оглед; в режим на хартия не праща поръчки
npm run engine:cli state     # какво се е случило досега
```

## Как се стига до сделка

```
OKX свещи + котировка ─┐
                       ├─> показатели ─> Claude ─> риск-двигател ─> OKX поръчка
Polygon (проверка) ────┘   (ATR, RSI)   (посока,   (размер, стоп,   (със стоп
                                        увереност)  тавани, EV)      на борсата)
```

Всяка стъпка може да откаже. Claude връща „изчакай" по подразбиране; риск-двигателят
отказва при широк спред, при разминаване между източниците, при достигнат дневен
лимит и при липса на измерено предимство. Всеки отказ се записва с причина —
`npm run engine:cli state` и екранът „защо няма сделка" четат точно тези записи.

**Claude е съветник, не изпълнител.** Не вижда капитала, не смята размер и не
може да заобиколи риск-двигателя. Аритметиката е в код и се тества; преценката е
в модела и се ограничава.

## Истинска търговия

Изисква **две** отделни разрешения, нарочно:

```bash
TRADING_MODE=live
ALLOW_REAL_ORDERS=true
```

Преди това: пусни седмици на хартия, изкарай поне 20 затворени сделки, погледни
`npm run engine:cli state`. Ако измереният процент печеливши е под колонката
„нужни + резерв" от `edge`, системата няма да търгува — и е права.

## Структура

```
engine/                  двигателят (Node, TypeScript, без зависимост от платформа)
  src/config.ts          настройки + сметките за точката на нулата
  src/risk/              размер на позиция, тавани, предимство  ← сърцето
  src/exchange/          OKX REST v5, подписване, защитени поръчки
  src/market/            Polygon + сверяване на двата източника
  src/ai/                Claude (структуриран отговор)
  src/core/              пълният път на сделката + рутер на функциите
  src/compat/            заместител на base44 SDK-то (същият език, локални файлове)
  legacy/functions/      104-те стари функции, пренесени дословно
src/                     интерфейсът (React + Vite)
```

## За стария код

Старите 104 функции не бяха пренаписани, а **пренесени**: сменени са само
вносовете и платформата (`engine/scripts/port-legacy.ts`), логиката е недокосната.
Пренаписването им едно по едно е седмици работа и внася грешки в код, който
работи. Новите функции стоят отгоре и печелят при съвпадение на имена — така
пренаписването може да върви по една, без прекъсване.

Същото важи за интерфейса: `src/api/base44Client.js` вече говори с локалния
двигател, но държи същия външен вид (`base44.entities.Trade.filter(...)`).
Затова над 400 места в интерфейса останаха непокътнати.
